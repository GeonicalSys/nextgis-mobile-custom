Добавлена проверка реальной очереди SQLite и HTTP-запросов в изолированном
Android-приложении. Подтверждённый PostGIS-источник ЛИСЫ отправляет пользовательские
поля и геометрию без семи серверных полей: created_at, created_by, updated_at,
updated_by, deleted_at, deleted_by, deletion_operation_id. Локальные значения
истории, пользовательские нули и прежняя обработка обычных числовых NULL
проверяются отдельно.

Реализация фильтра принадлежит Maplib и учитывается его собственной карточкой.
Android-тест использует отдельную учётную запись, настоящий provider/outbox и
loopback HTTP. Проверяются точное совпадение сохранённого payload с запросом,
повторное получение metadata и отсутствие изменения пользовательских данных.
Чужая таблица либо неподтверждённая metadata не разрешают фильтрацию по одним
именам полей. Продолжение для старой очереди оформлено отдельно в
[карточке восстановления](android-20261126-legacy-recovery-229.md).

Связь с дорожной картой: REL-01. Финальная проверка текущего APK и native-сценария
ещё ожидается; прежние source/JVM-квитанции не означают приёмку этого кандидата.
Для выпуска 229 пользователь отдельно разрешил проверку только на эмуляторе.
Это не подтверждает работу телефона, живую клиентскую БД, опубликованные NGFP
или стандартный Full.

В выпуске 229 проверена отправка со старым составом полей. Служебные поля истории исключаются по подтверждённой схеме, бизнес-значения сохраняются. Результат входит в `native-release229-03-verified-cohorts`.
