# Зависимые списки NGFP

Механизм встроен в APK: `maplib` разбирает данные и граф связей, `maplibui`
управляет существующими `combobox` и обоими полями `double_combobox`. Нет JS,
SQL, сетевых запросов при выборе или нового типа элемента формы. Без расширения
старые формы сохраняют прежнее поведение. `input_search`/AutoTextEdit, radio и
числовые поля пока не поддерживаются; неподдерживаемая привязка блокирует Save.

## Формат v1

NGFP по-прежнему содержит ровно `form.json`, `meta.json`, `data.geojson`.
Расширение хранится в `meta.json.lisa_form_dependencies`:

```json
{
  "schema_version": 1,
  "tables": {
    "companies": [{"id": "c1", "name": "Компания A"}],
    "staff": [{"id": "e1", "company": "c1", "role_id": "p1", "role": "Мастер", "name": "Тестовый сотрудник"}]
  },
  "fields": [
    {"field": "contractor", "table": "companies", "key": "id", "value": "name", "label": "name", "filters": []},
    {"field": "jobtitle1", "table": "staff", "key": "role_id", "value": "role", "label": "role", "filters": [{"column": "company", "field": "contractor"}]},
    {"field": "eployee1", "table": "staff", "key": "id", "value": "name", "label": "name", "filters": [{"column": "company", "field": "contractor"}, {"column": "role_id", "field": "jobtitle1"}]}
  ]
}
```

Все клетки таблиц — строки. `key` задаёт устойчивую идентичность варианта,
`value` — текст, записываемый в существующее STRING-поле слоя, `label` — подпись.
Фильтры объединяются AND и сравнивают колонку строки с **key** выбранного
родительского варианта. Повторения key в таблице связей удаляются из списка;
значение и подпись данного key обязаны совпадать во всех строках. Несколько
полей могут использовать одну таблицу. Порядок правил и вкладок не влияет на
зависимости. Каждый родитель должен иметь собственное правило в этом блоке.

Циклы, отсутствующие таблицы/колонки/поля, повторные привязки и неизвестная
версия отклоняются. Фиксированного числа уровней нет; ресурсные пределы v1:
512 полей, 100000 строк суммарно, 4 MiB текста определения на открытии формы.
Это не API произвольных выражений и не доступ к внешним таблицам.

## Состояние и сохранение

Новая форма начинается без выбора, даже при одном варианте или `last=true`.
Пока родители не выбраны, ребёнок недоступен. Смена поля очищает всех потомков,
включая ответвления и общие дочерние узлы. Пустой список отличается от ожидания
родителя. `Нет значения`, пустота и Unicode-пробелы означают отсутствие выбора;
`не применимо` допустимо, если явно присутствует в данных справочника.

Открытая форма закрепляет определение, выбранные key и исходные значения
существующего объекта. Ключи `lisa_cascade_pin`, `lisa_cascade_keys`,
`lisa_cascade_original` входят в Activity Bundle и typed `controlState`
`FeatureFormDraftStore`; отдельная миграция draft storage не нужна. Пустой pin
означает отсутствие правил при открытии. Обновление NGFP не меняет открытый
сеанс или восстановленный черновик. При несовместимом новом layout Save
блокируется, черновик остаётся.

Перед окончательным Save, включая Back, сначала создаётся durable checkpoint,
затем идут project scripts, проверка принадлежности вариантов и штатный
`required`, затем SQLite/вложения. Сброшенное управляемое поле явно записывается
как SQL NULL. Незаполненный необязательный ребёнок допустим.

Старые отсутствующие/неоднозначные текстовые значения показываются как
«сохранённое значение», автоматически не заменяются. Допускается сохранить
прежнее значение только вместе с неизменными исходными предками. Новая неверная
комбинация блокируется. Одноимённые варианты с разными ID сохраняют идентичность
в черновике; после записи текста в слой различение тёзок теряется. Для устранения
этого ограничения нужна отдельная миграция атрибутов на ID.

## Владельцы и доставка

Access-синхронизатор `C:\MyAccess\webgis-sync` генерирует справочники и обе ветви
аудита по ContractorID/PostTypeID/EmployeeID. Он остаётся вне Git и читает Access
только read-only. Его `owner=contractordocs-sync-v1` относится к генератору,
универсальный Android parser не привязан к Access или модулю аудита.

NGW хранит legacy NGFP без изменения серверного кода. Штатные клиенты не
исполняют расширение; сохранение через преобразование в современную web-форму
может удалить его. Синхронизатор запрещает такое преобразование и проверяет
побайтный download после публикации. Другие вопросы, field bindings и настройки
сохраняются. Данные/схема PostGIS не меняются.

Desktop `stand_project` collect/apply переносит NGFP, clone сохраняет весь блок
зависимостей: локальные/Access-ID в нём **не** являются NGW resource ID и не
remap-ятся. Контракт должен сохраняться при следующих доработках publisher.

Порядок интеграции: Merge Commit maplib → Merge Commit maplibui → обновление
root pins и Squash app → Squash desktop. Версии APK/плагина в этой задаче не
поднимаются; выпуск и активация на рабочих ресурсах — отдельное действие.

Проверки: `CascadingListsTest` (включая цепочку 83 уровней),
`CascadingFormsTest` (реальные NGFP/SQLite/draft/recreate на изолированном Android),
тесты сохранности метаданных и guard Access, тест clone в обоих QGIS runtime.
