# app — Android-приложение Lisa/Belka

## Одна подпись квартала в локальных тайлах

`LocalVectorTileLabelTest` проверяет синтетический NGW-backed SQLite слой через
настоящий loopback MVT и native MapLibre. На границах тайлов и после смены зума /
повторного применения стиля видна одна Point-подпись с ID исходного квартала;
pixels подтверждают подпись, заливку и контур. Используются один VectorSource и
три прежних style layers, без нового объектного слоя. Snapshot ожидает native
idle и новый полностью отрисованный кадр после смены камеры/размещения.
Пиксельная проверка также дожидается заполненного кадра в ограниченном времени:
асинхронная перестройка карты может вернуть пустой snapshot между состояниями.
Этот отдельный тест входит
в Related `map`; классическая style matrix по-прежнему исключает vector tiles.

## Общая история треков и проверки обычных стилей

«Мои треки» — общая история установки, одно служебное представление на карте.
MainApplication импортирует старые источники до открытия map helpers. Switch
во время записи запрещён. SharedTracksTest проверяет общую историю и native
отрисовку; VectorStyleRenderingTest использует обычные synthetic SQL/GeoJSON
слои и исключает configured vector tiles. Related styles добавлен в каталог.
Исправление переноса читает настоящий `layers.db` и повторяет пропущенную
историю рядом с новыми общими треками. Native SharedTracksTest проверяет все
поля исходника, remap незавершённого сеанса и pending Stop после обновления.
Графический fixture отключает стартовый geo-dialog и синхронизирует camera и
видимость underlay с моделью. CI использует Xvfb/Mesa host OpenGL вместо
SwiftShader, который не отображает проверяемые подписи.

## Немедленная отправка и часы открытого проекта

MainApplication восстанавливает LocalChangesWorker всех downloaded workspaces.
Отдельный worker отправляет saved edits/outbox без полного sync и без изменения
его времени. ProjectSyncRunner подтверждает clock только после полного успеха
owning project со всеми account/children и пустой готовой очередью. LayersFragment
показывает ProjectSyncState активной карты и явное отсутствие подтверждения;
не использует старый общий timestamp. См. project-synchronization-user-guide.

Азимут и вынос имеют отдельные layout_azimuth_panel/layout_stakeout_panel.
Первый содержит расстояние, магнитный азимут, склонение и коррекцию, без стрелки,
звука или точности GPS; live measurement запускает controller без звука.
Второй восстанавливает состав исходного выноса b4c860d (2026-08-15): стрелка,
расстояние, точность, стороны света без компаса, звук и Close. Магнитных чисел и
строки коррекции в окне выноса нет; compass guidance/пороги сохраняются.
Обе панели используют адаптивное вписывание и независимые видимые действия.

## GPS после запуска и диагностика восстановления

«GPS в фоне» включён по умолчанию и запускает отдельный location foreground service
после открытия приложения. Гашение экрана и формы не снимают shared GPS lease;
через два часа вне приложения lease и тихое уведомление исчезают. Возврат
возобновляет получение. Выключение опции снимает только lease сервиса: открытые
экраны приложения, включая формы, продолжают владеть GPS через контроллер.
Track/Walk/stakeout сохраняют независимые lease.
Долгое восстановление автоматически попадает в существующую очередь диагностики
с raw/filtered/GNSS/power snapshot. Сетевая точка между обновлениями остаётся
видимой с ±accuracy и приблизительным возрастом, сохраняя исходный timestamp.
Проверки: BackgroundLocationPolicyTest, BackgroundGpsNativeTest и native
LargeTextLayoutTest для возраста сетевого измерения и настройки местоположения.


Завершение перетаскивания слоёв безопасно обрабатывает строку, ушедшую за
пределы видимой части списка, или обновлённый список. Если анимации не к чему
вернуться, жест завершается без падения: hover и ожидание прокрутки очищаются,
список остаётся доступен. Перестановки сохраняются прежним endDrag; порядок
модели и карты не меняется.

## Назначение

Общие панели и подписи адаптируются к крупному системному шрифту и display size:
перенос, понятное сокращение, затем локальное уменьшение при переполнении.
Азимут/вынос сохраняют X внутри доступной области, GPS-статус переносит значения,
а длинное название обхода — строку действий. Полный native Layout и реальные
touch targets проверяет `LargeTextLayoutTest`. Контракт:
[крупный интерфейс](../../docs/architecture/ui-accessibility.md).

Нижняя панель при обычном масштабе остаётся компактной: координаты/масштаб
в первой строке, GPS/спутники и точность — во второй. Когда координаты переносятся,
масштаб переходит к коротким GPS/точности и помещается с ними на одной строке.
Высота и скорость удалены.
Дополнительный 40 dp footer не резервируется; логотип/attribution поднимаются
над нижними видимыми элементами. Прозрачные слоты свёрнутого меню добавления
передают карте тапы и жесты. Native LargeTextLayoutTest проверяет стандартную
высоту панели на разных DPI, полный touch stream и видимый плюс.

Ручной sync без активной сети сообщает «Отсутствует подключение к интернету»
до запуска очереди. При пропаже соединения диалог/уведомление ошибки использует
тот же текст. LAN/VPN не требует внешнего validated Internet. Обход продолжает
ожидать свежий GNSS после потери сигнала без автоматической паузы; пауза остаётся
явным пользовательским действием. Native `SyncOfflineAndWalkGpsTest` проверяет
реальный диалог, очередь, геометрию, point lock и сохранение ручной паузы.

Фоновая синхронизация аккаунтов и отправка треков ждут сеть без ошибки/багрепорта.
Guards перед dispatch/queue/upload закрывают отключение после network constraint;
recovery journal и SQLite sent=0 остаются для повтора при подключении.

EmulatorNetworkFixture ждёт активный connected Wi-Fi после переключения radios:
асинхронное отключение mobile data не должно дать ложную готовность сети.
Перед следующим тестом fixture ждёт завершения восстановления Wi-Fi adapter.
CI запускает восемь TrackUploadTest после новой установки APK, отдельно от
recorder fixtures. Это изоляция проверки; runtime network guards прежние.

BackgroundLocationWarningTest возвращает ограниченное приложение из фонового
состояния системной кнопкой Back. Внутренний broadcast ActivityScenario может
задерживаться при RUN_ANY_IN_BACKGROUND=ignore; тест по-прежнему ждёт RESUMED,
проверяет реальное предупреждение и отсутствие автоматической записи.

Сообщения о начале/успешном завершении синхронизации выключены по умолчанию
(`show_sync=false`); явный выбор пользователя сохраняется. Ошибка очереди
показывает понятное уведомление независимо от этой настройки. Обязательный
тихий индикатор dataSync-службы живёт только до её завершения: inactive progress
и поздний callback уничтоженной службы его не публикуют повторно. Startup
основного процесса очищает оставшиеся индикаторы 519/520, сохраняя ошибки,
GPS и остальные уведомления. `SyncNotificationsTest` проверяет lifecycle
на API 26/36 и на изолированном Android 16 эмуляторе.

Запуск локального журнала проходит через общий `LocalLogInitializer` без
фиктивного URL и повторной подготовки backlog к отправке. Локальные логи,
пользовательский формат и delegating crash handler сохраняются. Автоматические
HTTP 5xx в GlitchTip ограничены десятью минутами; первый отчёт сохраняет адрес,
query, HTTP headers/response и предоставленный контекст без маскирования.
`DiagnosticsPayloadLimiter` ограничивает размер/глубину данных; HTTP streams и
хранилища проекта для этого не читаются. Fatal и disk replay проходят прежним путём. NGFP сравнивается по
каноническому JSON, чтобы порядок ключей сервера не вызывал ложную ошибку sync.
Проверки: `DiagnosticsHttpPolicyTest`, `LocalLogInitializerTest`,
`LayerFormHashUtilTest` и emulator-only `DiagnosticsNoiseTest`.

В «Мои треки» отправка на сервер включена по умолчанию; UID можно зарегистрировать
позже, без повторного включения галочки. Жёлтая отметка общего sync и строки
«Мои треки» учитывает sent=0 только при включённой отправке и подтверждённой
регистрации UID на выбранном сервере. До регистрации отметка скрыта;
сетевой сбой у уже зарегистрированного трекера её не снимает. Точки остаются
на устройстве до регистрации и успешной доставки, включая остановленный трек.
Контракт: docs/architecture/ngw-sync-and-storage.md.

Одна кнопка «Измерения» со значком линейки заменяет отдельные кнопки линейки
и азимута. Она открывает компактное меню: «Линейка», «Азимут от местоположения»,
«Азимут между точками», каждый режим запускается сразу. Кнопка скрыта во время
редактирования/измерения и возвращается после завершения. Существующий
show_ruler_measuring выключает только пункт линейки, сохраняя оба входа азимута.

Карандаш, создание по местоположению и обходом после выбора слоя предлагают
конкретную категорию с символом из стиля проекта. MapFragment сохраняет явные
начальные значения в geometry draft, для фонового обхода — в WalkSessionStore,
и передаёт их штатной форме. Отмена категории точки освобождает point lock
и сохраняет текущую фоновую запись. Тип и его родители уже заполнены;
повторное восстановление формы сохраняет последующие изменения пользователя.
Контракт: [выбор типа](../../docs/architecture/feature-type-creation.md).
StandardFeatureTypesTest проверяет все 40 категорий и связанные классы на
копиях стандартных форм и стилей без подключений и полевых данных.
CascadingFormsTest также проверяет видимую отмену для 40 категорий и понятное
сообщение при ошибке подготовки списка, без создания объекта.

NGFP-вкладки закреплены сверху и переключаются взмахом по содержимому. Общие
условные требования (`lisa_form_rules`) работают offline и перед Save/Back Save.
V2 добавляет visibility по тем же условиям: комментарий появляется при снятой
отметке, скрывается без очистки и восстанавливается из draft. Скрытые поля не
блокируют Save. Чёткие подписи, рамки, перенос названий и нижняя кнопка Save
применяются ко всем формам; FormAppearanceTest проверяет обе темы.
`ConditionalRequiredFieldsTest` проверяет маркеры, inactive fields, SQLite,
статический required, pin/recreate/durable recovery и повреждённые настройки.
[Руководство](../../docs/guides/form-behavior-user-guide.md).

Каскадные поля отображаются отдельно: каждый список имеет собственную подпись,
полную ширину и отступ. Старые сдвоенные элементы с декларативным каскадом
разворачиваются при открытии, без обновления серверной формы. Native regression
проверяет многократные свайпы над включёнными списками, флажком, комментарием
и пустой областью, сохранение выбора и исключение выделения текста/подписи.

В списке слоёв жёлтая точка отмечает несинхронизированные изменения конкретного
слоя. Она и общий индикатор sync обновляются из одного фонового снимка outbox,
включая удаления и скрытые слои. После подтверждённой отправки отметка исчезает.
Native `LayerPendingChangesTest` проверяет изоляцию слоёв, переиспользование
строк, поворот и удаление последнего объекта до очистки синтетического outbox.

Приложение использует встроенные зависимые NGFP-списки из maplib/maplibui;
`CascadingFormsTest` проверяет реальные UI/SQLite, очистку обеих ветвей,
черновик и восстановление после обновления метаданных. Пользовательский workflow:
`docs/guides/cascading-form-lists-user-guide.md` consuming root.

В выборе внешнего GNSS Bluetooth Classic/LE показывает последнее измерение
сигнала в дБм под именем устройства. −45 дБм сильнее −80 дБм; недоступное значение
подписано «Сигнал не измерен». Повторный поиск обновляет измерения, одинаковые
имена сохраняют отдельные строки и прежнюю адресную идентичность. Это Bluetooth,
а не качество спутникового фикса; USB/TCP не показывают RSSI.

Продуктовый Android-модуль: запускает GISApplication, предоставляет основной
UI и Map host, управляет брендами, preferences, release и self-hosted update.
Launcher и экраны intro/about получают иконку через flavor-ресурс
`app_launcher_icon`: Lisa использует `ic_launcher_lisa`, Belka — отдельный
`ic_launcher_belka` во всех пяти Android density buckets. PNG-символы точечных
стилей лежат в `src/main/assets/marker_icons/*.png`; имя файла без расширения —
id изображения в MapLibre. Карта использует MapLibre Android `13.0.2` с явным
OpenGL backend вместо Vulkan-default artifact.

Текущий production выпуск Lisa/Belka — `3.1.2.29` / `223`, сопряжённая
maplib — `3.1.2.29`. Lisa Debug и maplib debug остаются `3.1.2.23` / `218`.
APK version matrix выполняется после закрытия library/app PRs; в этом цикле
публикуются только Lisa Release и Belka Release, Debug не публикуется.

Внешний Pigo по BLE использует собственную пару UART-каналов и может получать
BESTPOSB без предварительного запуска PiMock. HUD сбрасывает старое качество
через 8 секунд без данных. Холодный старт Pigo/PiRat требует физического smoke.

## Основные сценарии

- Поля, отмеченные обязательными в настройках NGW-слоя, проверяются при Save
  и при сохранении через выход из стандартной/NGFP формы, в том числе offline.
  «Нет значения» считается заглушкой только при проверке обязательности;
  «не применимо» допустимо. После изменения флага на сервере нужна успешная
  синхронизация настроек слоя. Старые APK флаг игнорируют. Native
  RequiredFieldsTest использует синтетические формы и локальную SQLite.

- До ручной записи `TrackPowerWarning` проверяет политику GPS в энергосбережении.
  При ограничении на погашенном экране предлагает настройки батареи или явное
  продолжение. Resume и сообщение живого сервиса обновляют предупреждение;
  Doze «не спрашивать» его не скрывает. Настройки не запускают запись автоматически.
  Отдельный `BackgroundLocationWarning` проверяет эти ограничения при открытии
  карты и Resume без активного recorder, включая запрет фоновой работы и Doze
  оптимизацию. Полоса предупреждения с «Настроить» ведёт к соответствующим
  системным настройкам. При одном доступном действии системный запрос или
  страница открывается сразу; список выбора показывается только при нескольких
  ограничениях. Неизменная ситуация не повторяется до нового запуска;
  изменение ограничений вызывает новое предупреждение, устранение убирает его.

- GPS callback карты не проверяет незавершённые треки через SQLite: использует
  durable `track_recording_enabled` и фоновый incremental track reload maplib.
  Геодезия, частота координат и запись точек не изменены.
- При создании карты и возврате из системных настроек `MainActivity` проверяет
  геолокацию, доступ к учётным записям и legacy storage. Уведомления не входят
  в обязательную проверку: их разрешение запрашивается только при включении
  соответствующей функции в настройках. Повторный
  отказ ведёт к странице разрешений приложения. `GET_ACCOUNTS` не читает
  содержимое контактов; Bluetooth, background location и установку APK
  приложение запрашивает по контексту действия. Пока служба не создала трек,
  меню не утверждает, что запись идёт; явный отказ сопровождается предупреждением.
- запуск приложения и открытие карты;
- прямой импорт raster MBTiles и явный перенос локальных TMS-подложек из
  установленного старого Lisa Debug в активный Geonical-проект; «Новая подложка
  из файла» показывает имя файла и прогресс, не SAF document id; bridge проверяет
  оба package/signing certificate, не переносит project/account/vector/track
  data и не удаляет источник; перенос показывает текущий объём/тайлы, допускает
  явную отмену и подтверждённый выход, а после inactivity timeout один раз
  повторяет зависший source, не оставляя sync заблокированным; обновлённый
  pre-registry Debug не преобразует исходные папки до экспорта;
- сохранение отрисовки карты после возврата из настроек/другого приложения,
  выключения экрана и пересоздания view: `MapFragment` передаёт MapLibre полный
  lifecycle, освобождает старый native renderer и запрашивает repaint при resume;
  после фактического применения project style выполняется короткий continuous-
  render burst с presentation invalidation и камерой без смещения; recovery
  считается успешным только после реально исчезнувшего foreground, а оставшийся
  загрузочный foreground снимается без full style reload;
  все поддерживаемые версии используют `SurfaceView`, который умеет пересоздать
  потерянный EGL-контекст; на Android 8–9 выключен tile prefetch. Искусственный
  потолок 5/30 FPS и постоянный `CONTINUOUS` на Android 8–9 не используются:
  в покое renderer остаётся в `WHEN_DIRTY`, recovery на всех API — короткий
  burst и возврат к прежнему dirty-режиму. Позднее касание уничтоженного
  view отбрасывается до обращения к MapLibre;
- вращение карты двумя пальцами только после явного разрешения кнопкой рядом с
  текущим местоположением; состояние и bearing сохраняются, запрет возвращает
  север вверх, а разрешённый rotate начинается сразу при одновременном
  двухпальцевом касании и не отключается начавшимся pinch. Камера не опускается
  ниже `7.5`. Кнопка местоположения также возвращает север, поднимает zoom до
  `12`, если он был меньше, а без координаты переходит к охвату первого
  пригодного слоя, центрирует карту по нему и выставляет zoom `12`;
  все включённые raster-подложки доступны с zoom `7`, а режим фона карты
  «Светлый» использует сплошную заливку `#FFFFFF` без повторяемой текстуры,
  в том числе после переключения с нейтрального или тёмного фона;
- управление слоями, edit/walk/track через библиотеки;
- якоря подписей полигонов располагаются внутри заливки, а для MultiPolygon —
  внутри одной из его частей, с учётом отверстий;
- меню добавления слоя начинается с «Загрузить проект»: radio-список с
  разделителями и прокруткой, загрузка по кнопке; «Добавить слой NGW по
  URL» скрыт;
- в настройках карты «Не отключать экран» включён по умолчанию;
- тяжёлые opt-in `local_vector_tiles` обслуживаются ограниченным loopback-
  сервером: максимум две одновременные сборки и очередь 16, с отменой старого
  поколения карты и retry вместо неограниченного роста потоков/heap;
- новый скетч начинается сразу после выбора слоя: точка или первый узел линии/
  полигона ставится в экранную проекцию центра камеры, следующие узлы добавляются
  тапами; midpoint-вставка работает для линий, полигонов и линейки, дополнения
  касанием/overflow и дублирующей нижней кнопки `+` нет;
  кнопка формы активна после появления геометрии и проходит тот же путь
  проверки/сохранения, что верхняя кнопка «Сохранить»; повторное нажатие не
  открывает вторую форму; успешное сохранение нового или существующего объекта,
  включая подтверждение формы атрибутов, полностью завершает редактирование,
  снимает выделение и возвращает стандартный экран карты; Undo/Redo отменяет
  или возвращает одну реальную правку за одно нажатие и хранит до 100 изменений
  без служебных снимков выбора узла
  и callback-снимков, отличающихся только CRS; в инструменте измерения те же
  кнопки по одной отменяют и возвращают добавление или перенос точки активной
  MapLibre-линейки и сохраняют её состояние при пересоздании экрана;
- ручное создание редактируемых точечных, линейных и площадных слоёв, импорт
  редактируемого локального GeoJSON в WGS 84, включая стандартные записи EPSG:4326,
  и упрощённый импорт каждой координаты KML/GPX как отдельной точки одного слоя;
  выбор слоя для нового объекта не скрывает выключенные редактируемые слои, а выбранный
  выключенный слой автоматически становится видимым и сохраняет это состояние;
- вынос выбранной точки, линии или границы полигона показывает собственную
  стрелку, расстояние, Android-точность, звук и Close. Числовой магнитный азимут
  и коррекция находятся в отдельной панели измерений «текущее положение → точка»/
  «точка A → точка B», без звука, стрелки и GPS-точности. Геодезия WGS84 и WMM2025
  сохраняются; compass heading сглаживается круговым фильтром, без компаса
  стрелка выноса учитывает поворот карты. A/B и live-цель перетаскиваются;
  временная линия не записывается в проект. Пороги звука и отдельные GPS lease
  выноса продолжают работать при выключенном экране;
- обычный азимут и вынос не требуют Bluetooth-разрешений. При отказе Android
  запустить измерение приложение показывает сообщение, завершает live-режим и
  освобождает GPS, звук и уведомление; после выдачи доступа к местоположению
  измерение можно начать заново;
- карта показывает свежую позицию GPS (чип, mock или native NMEA) с кругом точности в метрах и
  сектором точности компаса (истинный курс, без коррекции выноса); ширина
  сектора следует за неопределённостью компаса, длина сохраняет 56 логических
  пикселей при смене масштаба. «Орбита-кольцо» оставляет прозрачное окно 21 dp
  с синей центральной точкой диаметром 6 dp. Синий обод утолщён наружу на 1 dp
  до радиуса 13 dp за счёт белого обода; внешний радиус 15.2 dp и тёмная кромка
  сохранены. Заливки GPS и компаса не перекрывают окно, поэтому небольшой
  точечный объект на текущем месте виден под курсором. Сектор имеет белый и
  синий контуры поверх полупрозрачной заливки. Курсор — кольцо и вращающийся по его краю
  треугольник: компас приоритетен даже на месте; без него используется курс
  движения, а на остановке остаётся круг. Heading старше 500 мс или UNRELIABLE
  сразу отключает сектор и переключает направление без нового GPS. Компас
  слушается только пока карта в foreground. Network — запас без GPS. Поддерживает approximate permission
  и скрывает позицию после 8 секунд без
  пригодных измерений. Resume читает snapshot общего источника записи, без
  возврата к координате выключения экрана. Трек и обход сохраняют GNSS чипа, mock приёмника или native NMEA;
  чип сглаживается с учётом остановок, пешеходов и автомобилей до 160 км/ч, mock и NMEA — как есть, не грубее 2 с / 1 м.
  Внешний GNSS читается из NMEA или ComNav BESTPOSB (Bluetooth Classic/LE, USB, TCP/IP) без Mock Location; HUD справа от компаса показывает фикс/плав/авто.
  Пока приёмник выбран, соединение переживает Home и выключенный экран.
  Общие → «Расширенное логирование» пишет GNSS/NMEA в HyperLog, включая координаты.
  Пропуски GPS разделяют трек на сегменты, а обход требует явного продолжения.
  `gnss_input` выбирает системный или внешний источник; старые переключатели остаются пояснениями.
  Кнопка человека под линейкой раскрывает «Пешеход» / «Пешеход + машина».
  Пешеходный трек пропускает движение быстрее 30 км/ч и автоматически продолжается
  новым сегментом после замедления. Повторное нажатие при записи сразу завершает её.
  Активный человек оранжевый, красная точка увеличена; режим сохраняется при перезапуске.
  Цвет различает запуск, подтверждённую запись и ошибку. При выключенной системной
  геопозиции Start сначала предлагает открыть настройки Android.
  См. [контракт GPS](../../docs/architecture/location-pipeline.md).
- crash recovery: запись трека возобновляется без диалога, затем recovery hub
  последовательно предлагает черновик обхода, обычной геометрии и формы атрибутов;
  пустой обход, чей сервис не подтвердил первый snapshot, очищается тихо, а
  реальный stopped/foreign-map owner предлагается продолжить, удалить или
  аварийно сбросить; подтверждённый сброс есть также в общих настройках и
  затрагивает только состояние обхода;
  восстановленный Polygon сохраняет заливку, внешнее кольцо и только реальные
  отверстия без удвоения узлов; после cold Continue дополнения обходом красный
  контур и заливка не мерцают, а Stop возвращает редактируемые вершины; раннее
  Continue ждёт принадлежности edit sources текущему MapLibre style, а вход в
  обход удаляет параллельный черновик обычного редактора того же скетча;
  восстановленные LineString/MultiLineString показываются без polygon fill;
- редактирование геометрии: выход крестиком на нижней панели (`cancelEdits`),
  причём для нового объекта сначала требуется подтвердить удаление скетча; после
  подтверждения приложение возвращает сразу на карту, а не в пустую панель
  выбора действия; у линии/полигона выбранная вершина красная, а её следующая
  вершина и редактируемый сегмент в пределах той же части/кольца оранжевые;
- измерение площади линейкой всегда подписывается в гектарах;
- сохранение `GTMultiPolygon`: невалидный контур исправляется в один
  многокомпонентный feature до единственной формы атрибутов; простой Polygon и
  линии автоматически не исправляются; ручной MapLibre-конвертер сохраняет CRS
  контейнера и колец; одноточечный/слишком короткий контур останавливается до
  repair с сообщением «Недостаточно точек»;
- невалидный обычный Polygon остаётся в редакторе; самопересечение получает
  отдельное сообщение «Обнаружено самопересечение», а не ложное «Недостаточно точек»;
- идентификация объекта: список совпадений и верхняя панель используют
  `feature_label_field`; форма атрибутов в нижней панели доступна только если
  слой допускает редактирование (`isEditingAllowed`); слой с режимом
  `local_vector_tiles` отдаёт локальные атрибуты даже при выключенной отрисовке,
  не включая её, тогда как выключенный классический слой пропускается;
- выбор и переключение проектов по списку только из имён: строка выбирает
  radio, «Открыть» открывает карту, «Отмена» оставляет текущий проект; раздел
  «Настройки → Проект» с Web GIS-реквизитами, созданием пустого local workspace,
  локальным переименованием и удалением локальной копии; создание и активация
  выполняются под одним lease, а при сбое прежний workspace восстанавливается
  до удаления неактивного stage. Чистая установка до
  первой карты уже имеет активный «Локальный проект», а обновление один раз
  добавляет туда прежние standalone-слои без удаления их исходной копии;
- сохранение «Мои треки» наверху списка слоёв при создании и открытии карты;
- сохранение дефолтного `OpenStreetMap Standard aka Mapnik` внизу списка каждой
  карты, включая новый Collector workspace;
- завершение batch import только после фактического MapLibre style/source apply;
- продолжение незавершённого Collector import только внутри записанного project
  UID: чужой workspace не получает его SQLite-таблиц, а после возврата удаляются
  только app-marked unpublished layer stages; legacy unmarked каталоги остаются;
- индикатор синхронизации всё время видимого lifecycle двусторонне сверяется с
  worker/lease state: запускается либо останавливается даже при пропущенном
  start/finish broadcast; вокруг иконки кольцо без процентов отражает взвешенные
  слои и реальные фазы push/download/apply, скрывается вместе со spinner;
- проверка несинхронизированных правок для точки на sync-кнопке выполняется
  последовательно в фоне, а результат старой карты или уничтоженного view
  отбрасывается. Чужой early finish не останавливает spinner/foreground worker;
- длительное нажатие sync-кнопки с подтверждением перепроверяет пропущенные
  серверные геометрии, обходя часовой checkpoint `SYNC_NONE`; обычное нажатие
  сохраняет стандартный режим и всё ещё получает новые server counts;
- ручная и scheduled синхронизация по умолчанию обходят все загруженные проекты; общая настройка может ограничить их открытой картой;
  все account обрабатываются одним serial foreground worker под одним lease,
  без параллельного дублирования через `ContentResolver.requestSync`; повторный
  запуск отклоняется. При попытке переключить, создать, переименовать или удалить
  проект, загрузить слой или подложку во время sync приложение предупреждает и
  предлагает корректно прервать её. Read-only сетевое ожидание закрывается сразу,
  tracked apply откатывается транзакцией, а один уже отправленный server write
  получает однозначный ответ перед освобождением lease. Запросы во время
  fill/rebuild по-прежнему ждут завершения фоновой операции;
- перед account sync приложение безопасно сводит старые managed-дубликаты слоя
  к одной копии только после backup и только при отсутствии pending changes;
  edited-копии блокируют sync без автоматического удаления;
- ручной и системный sync используют `dataSync` foreground execution, а
  durable marker после process death запрашивает повтор только для того же
  account/workspace; clean finish снимает marker;
- массовый incremental pull не создаёт построчные spatial-cache уведомления:
  R-tree перестраивается один раз, а style props применяются к отдельному
  snapshot, не к live MapLibre feature;
- полный untracked snapshot потоково применяется из временного файла одной
  SQLite-транзакцией, отдельные невалидные геометрии пропускаются без удаления
  их прежних локальных копий, а MapLibre получает один reload после account-pass;
- добавление vector/raster NGW-слоя по прямому URL, включая проверенный guest fallback;
- получение ресурсов, подготовленных desktop QGIS-плагинами, только через
  NextGIS Web/Collector или явный import поддерживаемого portable artifact, без
  чтения desktop workspace;
- настройки приложения и Android permissions/services;
- автоматическая проверка Lisa/Belka updates после запуска, включая восстановление
  окна в новом процессе, с повтором при сетевом сбое; установка с продолжением после
  выдачи Android-разрешения на установку;
- экспорт/очистка сохранённых layer backups.

## Ограничения

- Geonical не может читать private storage Debug напрямую. Перенос доступен
  только после установки совместимой Debug bridge-сборки с прежним сертификатом
  и только в уже выбранный активный проект. Версии `3.0.3.2`/`3.0.3.3` не дают
  надёжной source-project identity для автоматического сопоставления.
- Export provider отдаёт только перечисленные локальные TMS-подложки через
  read-only content URI; accounts, credentials, registry, vector layers, tracks
  и feature data не входят в контракт.
- Cross-package stream может быть отменён пользователем или watchdog после
  отсутствия новых байтов; это завершает worker и освобождает lease до следующей
  операции с проектом.
- `lisa` и `belka` — отдельные product flavors.
- `app`, `maplibui` и `maplib` должны разрешать один MapLibre backend:
  `org.maplibre.gl:android-sdk-opengl:13.0.2`; generic `android-sdk` версии 13
  использует Vulkan и возвращать его в production нельзя.
- `MapFragment` должен реализовывать актуальный `MaplibreMapInteraction`.
- Каждый созданный MapLibre `MapView` должен получить согласованную пару
  `onCreate/onStart/onResume` и `onPause/onStop/onDestroy`; старый view нельзя
  оставлять привязанным к `MapDrawable` после `onDestroyView`.
  `maplibre_renderTextureMode=false` на всех API; на API 26–28 tile prefetch
  выключен. Потолок FPS и постоянный `CONTINUOUS` на Android 8–9 не
  используются.
- Не дублировать GIS model/storage из `maplib`.
- Не читать `Q:\standart_profiles`, `variables.py` или QGIS plugin mirrors:
  межпроектный runtime contract — NGW API/Collector либо явный portable import.
- Self-hosted update принимается только для того же flavor/application/signing
  identity и с увеличенным versionCode. На Android 9–10 пустой archive
  `SigningInfo` дополняется legacy `signatures`, после чего сертификат всё равно
  сверяется по SHA-256 с manifest и установленным пакетом.
- Ожидание специального разрешения на установку хранится как одноразовый
  app-private pending manifest; после возврата manifest и APK проверяются снова.
- Production version принадлежит `defaultConfig`; Lisa Debug переопределяет
  version через `androidComponents.onVariants`. `versionCode`/`versionName` в
  `buildTypes` запрещены на AGP 9.x.
- Update repository использует ветки `lisa`, `belka`, `debug` непосредственно
  под `https://apps-geonical.ru/lisa-mobile`; сегмента `stable` в URL нет.
- Для каждого build variant один account type обязан одновременно использоваться
  в runtime `MainApplication`, `AccountAuthenticator` и `SyncAdapter`; release
  использует `com.nextgis.account.geonical`, debug — `com.nextgis.account.debug`.
- Реальные DSN, client secrets и signing credentials не входят в docs.
- GlitchTip получает автоматические error reports со stack/device/version и
  структурированными стадиями работы. SDK cache сохраняется при offline/5xx;
  WorkManager повторяет отправку без открытого экрана. Screenshots, view hierarchy
  и performance payloads отключены. [Доставка](../../docs/architecture/error-reporting.md),
  [руководство](../../docs/guides/bug-reports-user-guide.md).

## Диагностика

Slow/blocked touch queries и local tile pressure имеют bounded map_runtime
снимок, независимый observer и private journal для AppExitInfo после restart.
Local 503 указывает queue_full/heap_headroom и request id. Sync queue failure
сохраняет первопричину, этап, объём очереди и доступное место; данные очереди
не удаляются. [Контракт](../../docs/architecture/error-reporting.md).

Открытые GlitchTip issue и подтверждённые границы диагноза:
[разбор 2026-10-13](../../docs/reference/glitchtip-triage-2026-10-13.md).
У старого Debug AppExitInfo проверять source revision отдельно от времени доставки;
handled HTTP/permission report не считать uncaught crash.

- Карта/слои: сначала проверить callbacks `MapFragment` и состояние
  `GISApplication`, затем rendering docs.
- Чёрная карта при видимых Android-кнопках после возврата с другого экрана:
  проверить последовательность `MapLibreMapView.onStart/onResume`, первый кадр
  после resume, `MapLibre render recovery started/completed`, последующие
  `onPause/onStop/onDestroy` и отсутствие старой ссылки `MapDrawable` на
  уничтоженный view. `completed` не должен содержать одновременно
  `fully=false` и `loadingForeground=true`. Запись
  `cleared stale loading foreground` означает, что
  project layers уже были применены, но MapLibre не снял свой loading foreground
  после ограниченной серии repaint.
- На Android 8–9 после recovery не должно быть постоянного `CONTINUOUS` и
  `setMaximumFps`; в логе остаётся `tilePrefetch=false` и общий burst
  `MapLibre render recovery started/completed`.
- Полностью чёрный экран вместе с Android-панелями на Android 8–9: проверить
  `onLowMemory`, системные `GL_OUT_OF_MEMORY`/`EGL_CONTEXT_LOST`, запись
  `MapLibreMapView renderer=SurfaceViewMapRenderer` и `tilePrefetch=false`.
  `TextureViewMapRenderer` на этих API является неверной конфигурацией: его
  render thread не пересоздаёт surface после потери EGL-контекста.
- Crash `No Vulkan compatible GPU found` при открытии карты означает неверный
  MapLibre runtime artifact: штатный APK использует OpenGL и не требует Vulkan.
- Карта не вращается: проверить состояние кнопки вращения рядом с геолокацией и
  `map_rotation_enabled`; запрет вращения является штатным значением по умолчанию.
- Кнопка геолокации не перешла к слою без GPS: проверить, что хотя бы один слой
  имеет конечный и инициализированный `GeoEnvelope`; пустой проект сохраняет
  обычное сообщение об отсутствии местоположения.
- Неправильный бренд или launcher: проверить `app/build.gradle`,
  `app/src/<flavor>/res/values/launcher_icon.xml`, соответствующие
  `drawable-*` flavor resources и manifest metadata.
- Version change: запускать `tools\verify-apk-version-matrix.ps1`; не определять
  версию debug по basename APK.
- Update отклонён: проверить schema, branch/channel, identity, version,
  versioned URL, size/hash/certificate и доступность branch manifest; не
  отключать проверку для обхода ошибки. Запись `Updater APK validation rejected`
  показывает этап отказа; нулевое число archive certificates на Android 9–10
  означает сбой обоих PackageManager-представлений подписи.
- Обновление не предложено: сопоставить `Updater startup` (restore, focus,
  busy/companion, retry) и `Updater check`/`Updater manifest` по `id`. Журнал
  содержит branch, текущую/серверную версии, active/internet/validated и transports,
  HTTP status, elapsedMs и exception со stack trace. Нет системного VALIDATED —
  запрос всё равно выполняется при active+INTERNET; результат даёт сам сервер.

- После чистой установки нет «Локального проекта» или старые ручные слои не

  открываться executor-потоком удаления; переход на `MainActivity` открывает её

- Вылет `notify_insert → GeoEnvelope.width/GeometryRTree`: это регрессия bulk

  `LinkedTreeMap` ошибок при обновлении style.
- Удаление проекта затронуло Web GIS: это регрессия — штатный путь удаляет только
  active workspace после backup gate и не вызывает remote delete/account API.
- «Мои треки» оказался внизу: проверить прямой порядок `LayerGroup` и
  `MainApplication.checkTracksLayerExist()`.
- Курсор положения движется, но линия трека не появляется: сначала проверить
  `TrackerService.onStartCommand`. Если до Stop нет фактического Start и
  `accepted=0`, это lifecycle запуска сервиса, а не отбрасывание GPS-фильтром.
- Форма точки поверх активного обхода восстанавливается первой по UUID владельца.
  Проверить `MainActivity.maybeOfferCrashRecovery()` и `WalkSessionStore`; старый

- После crash пропала линия из обычного редактора: проверить HyperLog-события

- Crash `GeoJsonSource.setGeoJson` сразу после раннего Continue означает регрессию
  current-style readiness: в журнале сначала допустим `renderer attach deferred`,

- Трек или обход перестал расти в автомобиле: проверить причины
  `LocationTrackFilter` и наличие свежего GNSS. Network никогда не записывается;
  проверить пригодность следующих fix и автоматическое продолжение обхода после
  потери GPS; ручная пауза сохраняется до явного Resume.
- Вынос молчит или показывает «Ожидание GPS»: проверить возраст fix, provider/mock-флаг,
  системную громкость навигации, уведомление активного выноса и owner lease частого потока;
  accuracy mock GPS отображается, но не блокирует звуковую зону. Координаты и расширенные
  поля mock `Location` в прикладной debug-журнал не записываются.
- Save восстановленной формы упал после успешного insert: проверить
  `FormSave result ready`, `FormSave result received` и разрешение `layer_id`
  из активной карты; cold restore не должен требовать старый `mSelectedLayer`.
- Форма предлагается сразу после успешного Save: проверить terminal guard
  `ModifyAttributesActivity.clearFormDraft()` перед последующим `onPause()`.
- OSM исчез из Collector-проекта или поднялся выше остальных слоёв: проверить
  `MainApplication.ensureBaseOsmLayerAtBottom()` и индекс `0` активной карты.
- Sync завершён в журнале, но иконка продолжает вращаться: проверить
  `NGWSyncService.isSyncStarted()` и reconciliation в `LayersFragment`; состояние
  адаптера не должно зависеть от доставки broadcast. Кольцо прогресса читает
  `NgwSyncProgress.snapshot()` и не показывает проценты.
- Полевые точки выбираются, но появились только после restart: проверить
  completion post-fill reload и `MapLibre post-load verification`; pending-флаг
  очищается только из `MapFragment.setMapLayersLoaded()`.
- Выключенный `local_vector_tiles` не идентифицируется: проверить
  `LayerIdentifyPolicy` и сохранённый render mode; identify не должен менять
  видимость слоя.
- Самопересекающийся мультиполигон не перешёл к форме: проверить
  `MultiPolygon geometry repair failed`; при отказе пользователь должен остаться
  в редактировании геометрии без частично созданного объекта. Сообщение
  `converted repair is empty or invalid` для обычной «бабочки» означает
  регрессию передачи CRS.
- URL не импортируется: проверить parser, совпадение server URL с аккаунтом,
  response code, тип ресурса и `data.read`; отсутствие `data.write` — read-only,
  а не ошибка импорта.
- Локальный GeoJSON сообщает о неподдерживаемой системе координат: проверить
  `crs.properties.name`; отсутствие `crs`, CRS84 и распространённые имена
  EPSG:4326 являются WGS 84 и должны импортироваться.
- На Android 16 локальный GeoJSON дошёл до SQLite, но импорт прерван сообщением
  о safety level/transaction: проверить порядок bulk-write PRAGMA в `maplib`;
  настройки БД должны применяться до транзакции.
- Ручной или импортированный локальный слой нельзя редактировать: проверить его
  `is_editable` в конфигурации; для нового обычного слоя значение должно быть `true`.
- NGW-слой стал read-only после простого просмотра свойств: направление sync не
  должно меняться от начального события списка; managed Collector-слой с
  разрешённым редактированием можно вернуть из «только с сервера» в режим «в
  обе стороны» без удаления.
- KML/GPX не загружается: проверить расширение документа и `CoordinatePointParser`.
  Поддерживаются KML `coordinates` и GPX `wpt`/`rtept`/`trkpt`; пустой или
  повреждённый XML должен дать обычное сообщение и не оставить неполный слой.
- Веб ГИС принимает логин, но не появляется: сверить merged-значения
  `nextgis_accounts_auth`, `nextgis_accounts_auth_type` и runtime account type.
  Локальный отказ `AccountManager` должен оставить форму открытой и попасть в HyperLog.

## Независимый обход и создание точки

Телефон, landscape и планшет используют единый `layout_map_content`:
кнопка трека и панель обхода обязательны во всех конфигурациях. `MapControlRail`
перекомпоновывает инструменты в столбцы справа по фактической высоте view,
включая поворот без пересоздания Activity. Меню создания раскрывается влево
в отдельной нижней строке; компактная панель обхода прижата к низу карты,
слева от инструментов, и временно поднимается при раскрытии меню создания.
При достаточном месте панель — одна строка: название слоя и три значка
«Сохранить», «Пауза/Продолжить», «Отменить». Все нажатия требуют подтверждения;
назначения доступны по долгому нажатию и для TalkBack. Естественные цели — 48 dp;
длинное название переносится над действиями, которые при необходимости тоже
переносятся. После вписывания проверяются реальные области нажатия. Тематическая поверхность,
скругление и цвет основной кнопки соответствуют ЛИСА/БЕЛКА. Сообщение появляется
только при ошибке сохранения или блокировке управления создаваемой точкой.
Точность GPS и выпадающее меню отсутствуют.
Регрессии структуры resources и расчёта столбцов проверяются unit-тестами;
реальные нажатия и повороты требуют device smoke.

`MapFragment` возвращает обычные меню после передачи геометрии сервису,
подключает пассивный preview и отдельную `WalkRecordingPanel`.
Preview обновляется также прямым получателем событий сервиса и при `onResume`,
поэтому наличие или видимость панели не управляет показом записанной геометрии.
UUID точки записывается до выбора слоя; все walk-команды остаются закрыты до Save/Cancel.
После подтверждения дискеты сервис завершает запись, затем автоматически открывается
форма атрибутов. После подтверждённого FINISHED линия требует две разные вершины, каждое кольцо
полигона — три. При нехватке обход завершается без объекта и формы, с сообщением
«Собрано недостаточно точек, выхожу без сохранения». При достаточной геометрии
атрибуты нового или существующего объекта открываются через общий Save gate. Иконки toolbar получают независимое состояние;
после пересоздания меню доступность и прозрачность Save/Undo/Redo обновляются вместе.
`MainActivity` восстанавливает принадлежащую этой сессии форму раньше
дублирующего черновика геометрии. Полный контракт и ограничения проверки:
[crash recovery](../../docs/architecture/crash-recovery.md).

Курсор следует текущей сглаженной позиции независимо от ожидания начала линии;
круг не обозначает расстояние от стоянки. Подтверждение ходьбы и новые регрессии:
[GPS pipeline](../../docs/architecture/location-pipeline.md).

## Хранилище и обновление Debug

`UnderlayCatalogActivity` доступна из настроек и меню добавления: имя, формат, размер, проекты, переименование и подтверждённое удаление. В Geonical при установленном доверенном Debug каталог (не режим выбора слоя) показывает «Импортировать из старого приложения» в активный проект. `DebugCompanionInstaller` отдельно от self-updater обновляет доверенный старый Debug, продолжает после install permission и возвращает к подтверждению переноса в хранилище только для исходного проекта. Кэш и preferences разделены; обычный updater сохраняет свои identity checks. Контракт и ограничение текущего публичного канала: [shared-underlays](../../docs/architecture/shared-underlays.md).

Оба режима `UnderlayCatalogActivity` используют явную `AppTheme.UnderlayCatalog`
в manifest: у приложения нет общей AppCompat-темы. Отдельный layout размещает
штатный Toolbar над списком, а системные insets отводят место status/navigation
bars и вырезам экрана, включая Android 16. «Хранилище подложек» расположено
на первом экране настроек, сразу
после «Проект»; `SettingsActivity` открывает каталог так же, как управление
проектом. В «Общие» дублирующего пункта нет. При smoke проверять переход
«Настройки → Хранилище подложек», возврат и выбор подложки из меню добавления.

Проверка старого Debug запрашивает реальный exporter у `PackageManager`,
включая enabled/exported состояние; явное имя Activity в Intent не доказывает
её наличие. На старой доверенной сборке кнопка «Импортировать из старого приложения»
в хранилище подложек должна открывать предложение обновления. Отдельно проверяется пригодность опубликованного APK:
старый серверный канал сам по себе не гарантирует доступность exporter.
Busy сохраняется до перехода от проверки к следующему окну. Видимый диалог
блокирует повторное продолжение по focus, а возврат из Android Settings и
Package Installer явно маршрутизируется из `onActivityResult` MainActivity и
хранилища подложек.
Smoke должен пройти выдачу разрешения и установку без повторного permission
диалога и без новой ручной проверки обновления.

## Автоматическая приёмка на двух устройствах

`tools/verify-mobile-tests.ps1` разделяет Related на эмуляторе и обязательный
Full перед публикацией. Opt-in `fieldVerificationChecks=true` собирает только
отдельную Debug identity «ЛИСА автотесты», собственные provider/account/storage
и VerificationTestRunner. Static suites допустимы на явно выбранном смартфоне;
GPS/radio/crash сценарии остаются на эмуляторе. Новый тест автоматически входит
в required catalog, отсутствие маршрута блокирует runner. Полный receipt
проверяется Check-Publication по содержимому всех четырёх checkout.

LayerSelectionDialogTest проверяет три строки/геометрии и настоящие touches,
36 enlarged UI profiles. ProjectLayerSelectionTest проверяет штатное создание
со snapshot разрешённого проекта 1403; при отсутствии проекта нужно спросить
пользователя. Команды и ограничения: [автотесты](../../docs/runbooks/automated-tests.md).

Shared track/style native fixtures, MapEditingToolsTest and WalkCheckpointTest
wait for startup underlay migration to finish before acquiring recording leases.
TrackPersistenceTest disables sending while synthetic shared points exist, then
cleans its rows before restoring the preference.

LargeTextLayoutTest awaits the focused input window and a committed frame before
physical map taps after rotation, retaining actual touch/visible geometry checks.
MapEditingToolsTest waits for the recreated MapView's own map and sources before
creation actions, then checks camera coordinates after the form returns to the
visible map instead of reading a stopped SurfaceView. Geometry and saved SQL values remain checked.
Creation pans update native and model camera state together; regression checks
invoke the delayed legacy redraw and preserve the actual GPS centre and fractional zoom.
