# Отчёты об ошибках мобильного приложения

После установки версии с новой диагностикой отчёты об ошибках отправляются
автоматически. Пароль GlitchTip в телефоне вводить не нужно.

Если интернет отсутствует, приложение сохраняет отчёт на устройстве. После
появления сети повторяет отправку, в том числе фоновым заданием Android.
Запускать синхронизацию проекта специально для этого не требуется. После
падения можно снова открыть приложение и продолжить работу с восстановленным
черновиком. Не удаляйте данные приложения и не переустанавливайте его с очисткой:
это удаляет ещё не отправленные отчёты вместе с другими локальными данными.

Android может отложить фоновую доставку ради экономии батареи. Если приложение
было принудительно остановлено в настройках телефона, откройте его снова.
Очередь ограничена: при очень долгом отсутствии связи старейшие из более чем
256 обычных отчётов могут быть вытеснены.

## Как разбирать присланные ошибки

1. Откройте [багрепорты](https://apps-geonical.ru/errors/) и войдите под учётной
   записью администратора. Данные входа хранятся в согласованной локальной папке
   ServerAdmin/GlitchTip, в файле «Вход в багрепорты.txt».
2. Выберите проект **NextGIS Mobile**. **Setup verification** используется для
   синтетических проверок доставки.
3. Откройте ошибку. Смотрите время события, число повторов, тип и текст ошибки,
   стек вызовов, версию приложения, Android и модель устройства.
4. В тегах `brand` указан бренд, `environment` различает тестовые и рабочие
   сборки, `source_revision` — коммит кода сборки (`+dirty` означает локальные
   изменения), `operation` — последняя операция. Например, AZIMUTH — азимут,
   STAKEOUT — вынос, SYNC — синхронизация. Breadcrumbs показывают последние
   стадии работы и экраны перед ошибкой.
5. После исправления и проверки отметьте ошибку решённой. Новое появление на
   исправленной версии требует повторной проверки.

Приложение не прикладывает скриншоты, ZIP с проектом, координаты трека, значения
полей или полный GPS-журнал. Стек ошибки и сведения о программе передаются в самом
отчёте. Повторяющиеся перехваченные ошибки ограничиваются, чтобы одна проблема
не заполняла список; критические падения отправляются отдельно.

Если проблема видна на экране, но исключение не возникло, автоматического отчёта
может не быть. Для такого случая полезны описание действий и существующий пункт
«Поделиться логом» при включённом локальном логировании. Уведомления из GlitchTip
пока отключены: новые ошибки нужно смотреть в веб-интерфейсе.
