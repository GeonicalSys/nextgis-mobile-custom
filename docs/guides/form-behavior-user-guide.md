# Заполнение и условные поля формы

При добавлении нового объекта выберите слой, затем тип из списка с условными
обозначениями проекта. После рисования форма уже содержит этот тип. Например,
выбор типа полевой точки заполняет также её класс, если тип зависит от класса.
Если одинаковый тип относится к разным классам, классы подписаны в списке.
Выбор сохраняется в черновике. Для слоя без категорий остаётся обычное добавление.
Типы загружаются и для смешанных форм с заголовками, вкладками и обычными списками.
Длинный список типов прокручивается, кнопка «Отменить» остаётся внизу экрана.

Название поля находится над рамкой; внутри рамки показано введённое или
выбранное значение. Пустое поле предлагает «Введите значение». Длинные названия
в списках переносятся; нажатие открывает список выбора. Заголовки разделов крупнее
подписей полей. Светлая и тёмная темы сохраняют это оформление.

Названия вкладок остаются сверху при прокрутке полей. Для перехода нажмите
название или сделайте взмах по содержимому: влево — следующая вкладка,
вправо — предыдущая. После перехода открывается начало вкладки, введённые
данные сохраняются. Взмах работает поверх списков, чекбоксов, обычных комментариев
и по пустой области страницы. Выделение текста, долгое нажатие, подпись, фото и
элементы со своей горизонтальной прокруткой сохраняют собственные жесты.

Должность и сотрудник представлены отдельными широкими списками, каждый со своей
подписью и отступом. Выбирать их можно независимо; связь между ними сохраняется.
Старые формы со сдвоенными элементами каскада приложение показывает таким же образом.

Обязательность может зависеть от ответа. Например, снятый чекбокс пункта аудита
делает комментарий к этому пункту обязательным. У поля появляется звёздочка.
Если отметить пункт снова, требование снимается, а введённый комментарий остаётся.
Условия могут также управлять видимостью. В аудите комментарий появляется,
только когда отметка соответствующего пункта снята. Если отметить пункт снова,
поле исчезнет целиком; текст останется и вернётся при повторном снятии отметки.
Скрытый комментарий не мешает сохранить аудит. Он сохраняется вместе с данными,
поэтому скрытие не удаляет уже записанный комментарий существующего аудита.
Для видимых полей постоянная обязательность сохраняется при любом ответе.

Перед сохранением приложение проверяет все вкладки. Если не хватает значения,
показывает список пропусков, подписывает ошибку под полем и открывает первое поле.
Кнопка «Сохранить» находится внизу экрана и доступна при прокрутке. Выход с сохранением
проверяется так же. Пустота, пробелы и «Нет значения» не заполняют обязательное
поле; «не применимо» допустимо там, где предусмотрено справочником.

Условия работают без интернета. После изменения администратором обновите
проект и откройте новую форму: существующий черновик сохраняет прежние правила.
Сообщение о невозможности проверить условия означает, что форму нужно обновить
или передать администратору; введённые данные остаются в черновике.

Администратор задаёт правила отдельно для каждой NGFP, без изменения облачного
сервера. Для подготовки доступны сравнения значений, проверка пустоты и группы
«И»/«ИЛИ». [Формат и примеры](../architecture/conditional-form-rules.md).
В тестовой группе 803 это настроено для всех 12 форм аудита. Для проверки:

1. Установите APK с поддержкой нового оформления и видимости, затем синхронизируйте проект.
2. Начните новый аудит, например «Вывозка», и откройте вкладку с вопросами.
3. Снимите отметку пункта: появится обязательный комментарий. Заполните его.
4. Верните отметку: комментарий скроется. Снимите её снова: введённый текст останется.

Продолжение старого черновика использует прежние правила. Для проверки обновления
нужна новая форма; сохранение тестового аудита не требуется.
