# Цель и разрешения

Полностью сохранить исходную задачу: пользователь подключил A56 по ADB,
попросил поднять версию и подготовить приложение к публикации. Версия уже
3.1.2.31/225. Пользователь отдельно разрешил software-only эмулятор локально
и слияние именно library65/app88. Оба PR слиты. Это не разрешение реальной
публикации, нового merge, установки release поверх рабочего телефона,
GitHub Actions или paused desktop/PG/Office/Access/VM/AVD-business стадий.
Наш Android client — поддерживаемое приложение, отдельный Collector не нужен.
SM-X115 пользователь явно исключил: подключить невозможно, тесты не выполнять.

Не останавливаться на bump: расследовать наблюдаемые native FAIL, исправить
то, что подтверждено и доступно в scope, выполнить адресные регрессии и
зафиксировать фактические ограничения. Не ослаблять pixel/visible-ID/geometry/
layout expectations ради green. Некоторый FAIL может быть дефектом fixture;
source/JVM PASS не заменяет native приёмку.

# Непосредственное продолжение

После Full выполнен на неизменных source/APK bytes штатный
`Related -Area sqlite-render -AllowEmulator -SkipBuild` на software-only
read-only AVD:8 PASS/3 FAIL из11. Эти11 сценариев прошли на A56.
Новые failures: content/style/visibility generation (при capture4 active reads,
0 returned), field/point/track priority (все reads returned, pixel mismatch),
MultiPoint custom marker (6 returned/2 SDK cancellations, missing cyan marker).
Это разные наблюдения, ещё не общая доказанная причина. Existing PBF/provider/
UID diagnostics сохранены. Finally восстановил settings, закрыл console/process.
Run завершён; source правки теперь не нарушают его fingerprint. Полный command
и статус — `active-checkpoint.json` в private evidence. A56 stress уже выполнен
самим Full: не повторять его без новой причины/изменения.

Затем отделить исходные причины:

1. Два waiter MapEditingToolsTest ждут прежний path/GeoJsonSource. Использовать
   actual `getVectorRenderSourceId` и expected current SQLite provider,
   сохраняя все исходные form/gesture/undo/assertions.
2. LocationOrbitTest напрямую добавляет SDK BackgroundLayer, затем требует
   reordering от updateLocation. Это старый sensor-side-effect. Текущий
   контракт выполняет stack work только при structural operations: проверить
   normal structural API, не возвращать O(layer count) на sensor tick и не
   удалять проверку верхнего cursor band.
3. Pixel/label/alpha/legacy tiled failures — причины пока UNKNOWN. Explicit
   classic fixture напрямую строит factories, но normal async streaming
   lifecycle может вмешиваться; это лишь кандидат. Не просто заменить expected
   pixels или Source type. Проверить actual backend/URI identity/camera/labels.
4. RenderMemorySafety на A56 не прошёл width полного текста в dialog matrix;
   конкретный widget/профиль не записаны. Проверить bounds/картинку и owning
   showRenderMemoryStatus → dialog builder; app имеет общий FittedDialogs.
5. Mixed tracks chooser на A56 не дождался native idle в общем style Fixture.
   Возможны live heading/GPS или queued source rebuild, но причина не доказана.

Похожий upstream issue4890 и source CustomVectorTileLoader13.7.1 прочитаны;
они не доказывают причину нашего FAIL. Не писать upstream без поручения,
не менять установленный SDK/cache и не начинать bulk SDK build/download.

Адресные dependency plans выполнены. Последний расширенный plan7 paths:
exit0, analysis UNKNOWN; tests PLUGIN_ONLY, MapFragment/test-plan MAPPED.
Source context — live root/app/библиотеки/publisher; preserved JSON содержит
точные hashes/coverage и unresolved constraints. Это source discovery,
не whole-ecosystem acceptance. Перед новыми путями повторять impact; owner
root остаётся foreign, canonical index check/write требует его follow-up.
