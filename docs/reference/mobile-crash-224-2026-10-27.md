от14 октября с libsentry unwind. Группа объединяет abort, а не установленную

За две минуты до нового abort у того же процесса Pixel поступили два события45:

этих отказов; в момент abort нет достаточного heap/native snapshot. Новое событие68
на том же223 — acquisition без первой GPS координаты/schema2; новая узкая policy
для штатного ожидания уже существует. Срезы45=188,68=35,69=3 прочитаны полностью.

Для69 нужен следующий отчёт после падения и повторного запуска диагностического
APK. Если OS trace недоступен, коллектор сообщает явный статус; Android<30 не даёт
этого fallback. Отсутствие trace или отсутствие повтора не означает исправление.

### Уточнение предупреждения: только свободный остаток

В experimentalec71 диалог возник автоматически. Память специально не занимали,
сам диалог из ADB не вызывали. Но прежний soft RSS порог768MiB с64MiB резервом

разбора доступными оставались4367524KiB системной памяти; сам диалог поэтому
не доказывал общесистемную нехватку. Профилировщик имеет64MiB client buffer и
32MiB trace buffer плюс служебные расходы: он не объясняет гигабайтный рост.

По прямому уточнению владельца абсолютные used/RSS значения ПОЛНОСТЬЮ исключены
из условий warning/cache/work degradation. Не применяется и сам nominal RAM
class. Учитываются доступная системная память относительно OS threshold/reserve,
свободный Java heap и OS low-memory signal. RSS/native/used остаются только
числовой диагностикой. Неизвестный OS counter не приравнивается к нулю.
Это уже source изменение послеec71, требующее отдельной native проверки;
его нельзя объявлять подтверждённым предыдущим профилем. Автоматическое
