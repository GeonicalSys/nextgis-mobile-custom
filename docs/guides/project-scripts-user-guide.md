# Проверки мобильного проекта

Администратор может подключить к проекту дополнительные проверки. Они
помогают заметить связанные данные при заполнении формы. Для работы нужен
выпуск приложения с поддержкой правил проекта; старое приложение эти правила
не выполняет. Новые вопросы в форму из-за подключения проверки не добавляются.

## Аудит подрядчика

1. Синхронизируйте проект перед выездом, чтобы загрузить свежую историю аудитов.
2. Создайте новый аудит и выберите подрядчика.
3. Если за последний месяц у него были аудиты с замечаниями, приложение покажет
   предупреждение. Учитываются все десять типов аудита, загруженных в проект.
4. Прочитайте сообщение и подтвердите его. Оно не запрещает проводить аудит.
5. Заполните форму и сохраните. Проверка выполняется ещё раз перед сохранением;
   одинаковое уже подтверждённое сообщение повторно не показывается.

«Последний месяц» здесь — с того же дня предыдущего месяца по сегодняшний
день включительно. Если такого дня в предыдущем месяце нет, берётся его
последний день. Исправленное замечание тоже учитывается как бывшее замечание.
При редактировании уже существующего аудита это предупреждение не выполняется.
«Нет значения» в выборе подрядчика считается незаполненным значением.

История берётся с телефона. Если часть аудитов не загружена или доступна другому
проекту/аккаунту, она не участвует в проверке. Отсутствие предупреждения не
заменяет просмотр серверных отчётов. Перед важной проверкой обновите проект.

## Сообщения и сбои

| Сообщение/действие | Что делать |
|---|---|
| Предупреждение при выборе | Прочитать и нажать «ОК», продолжить заполнение |
| Предупреждение при Save | «Продолжить сохранение» либо «Вернуться к форме» |
| Проверка запрещает сохранение | Исправить указанное условие; данные формы остаются открыты |
| Проверку не удалось выполнить | Синхронизировать проект; при разрешённом продолжении учитывать, что результат неполный |
| Используется предыдущая версия правил | Повторить синхронизацию при доступной сети; проверенная старая версия продолжает работать |
| Обязательная проверка недоступна | Сохранить черновик, обновить проект и обратиться к администратору |

Уже открытая форма и её черновик используют ту версию правил, с которой были
открыты. Обновление проекта применяется к следующим новым формам. Поворот
экрана не меняет версию. Если администратор удалил старый пакет на сервере,
не очищайте данные приложения до завершения нужных черновиков.

## Подключение правил администратором

1. Получите подготовленный каталог пакета. В нём должны лежать описание и
   исходники проверки; для изменения самой проверки нужен разработчик.
2. В QGIS откройте `stand_project` → WebGIS. Проверьте подключение и выбранную
   группу ресурсов, в которой находится нужный Collector-проект.
3. Нажмите **«Правила мобильного проекта…»**, укажите номер Collector и выберите
   каталог пакета.
4. Сопоставьте каждую строку с нужным слоем этого проекта.
5. Выберите поведение при сбое проверки. Для предупреждения об аудитах подходит
   «Сообщить о сбое и разрешить сохранение».
6. Нажмите **«Опубликовать»** и дождитесь подтверждения. Затем синхронизируйте
   проект на телефоне и откройте новую форму.

Для обновления получите пакет с новой версией и повторите эти шаги. Старые
версии не удаляйте, пока остаются использующие их черновики. Для отката выберите
сохранённый каталог предыдущей версии и опубликуйте его снова.

Публикация меняет настройки Collector и создаёт служебный ресурс пакета. Она
не изменяет вопросы аудита, справочники и объекты подключённых слоёв.
Перенос проекта через «Собрать эталон» требует постоянных имён слоёв; копирование
дерева ресурсов переносит пакет и соответствия автоматически.

Тестовый [проект 953](https://svetopaper.nextgis.com/resource/953) в группе 803
предназначен для проверки доставки правил и имеет слои только для чтения.
Создание аудита проверено на синтетических данных тестового эмулятора.
